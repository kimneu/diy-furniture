# Reduit-Konfigurator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Möbeltyp «Reduit» (Regalausbau eines Abstellraums) neben dem Sideboard, mit Formen gerade/L/U, Bauart selbststehend oder 5 Einbau-Arten, Nischen, Warnungen, Kosten.

**Architecture:** `index.html` bleibt die Hülle (Formular, Renderer, three.js). Reine Rechenlogik wandert in klassische Scripts: `shared.js` (Kataloge, `clamp`, `pack`, Verbindungs-Beschläge), `sideboard.js` (`computeSideboard`), `reduit.js` (`computeReduit`). Beide `compute*` liefern dasselbe Ergebnisobjekt; die Renderer verzweigen nur über `R.kind`.

**Tech Stack:** Vanilla JS (ES2020, keine Module, kein Build), three.js r128 via CDN, Tests mit `node --test` (Node 24), Browser-Check mit Playwright-MCP.

**Spec:** `docs/superpowers/specs/2026-09-25-reduit-design.md`

## Global Constraints

- Keine Build-Stufe, keine npm-Abhängigkeiten; GitHub Pages lädt Dateien direkt.
- Schweizer Rechtschreibung in allen UI-Texten (kein «ß»).
- Sideboard-Ausgabe bleibt bytegleich zum Snapshot (Characterization-Test).
- Scripts sind im Browser Globals; Node-Export nur über `if (typeof module !== 'undefined') module.exports = {…}`. Module rufen **kein** `require` auf (würde im Browser mit den globalen `const` kollidieren); Tests setzen `Object.assign(globalThis, require('../shared.js'))`.
- Masse in mm, Koordinaten wie Sideboard: x Breite (Mitte 0), y Höhe ab Boden, z Tiefe (hinten −D/2, vorne +D/2).
- Kein Push, kein PR.

## Abweichungen vom Spec (bewusst, im Spec nachgeführt)

1. **Ecke:** Seitentablare liegen nicht «von selbst» auf. Regel: Eck-Ende = **Eckleiste** (Leiste unter dem Stoss, an beide Tablare geschraubt); bei Wangen steht dort eine Wange.
2. **Kein Feld «Preis Massivholz»:** Kanthölzer und Latten haben unterschiedliche Preise; sie kommen aus der Jumbo-Preistabelle `BUY`.
3. **Speicherung:** ein `localStorage`-Eintrag; typ-spezifische Felder haben eigene Namen (`rw`, `rd` …), gemeinsame (Material, Platten) gelten für beide Typen. Ein Typwechsel überschreibt dadurch nichts.
4. **Massivholz** sind normale `rows` mit `kind:'solid'` (statt eigenem `R.solid`); `pack` ignoriert sie.
5. **Keine hintere Nische** (nachträglich entfernt: beim U immer gesperrt, sonst ein Randfall, der verwirrt).

## Review Focus

1. U mit `Tiefe links + Tiefe rechts ≥ Breite` → keine negativen Masse, Tiefen werden begrenzt, Warnung.
2. Nische breiter als Segment oder höher als oberstes Tablar → Nischenbreite begrenzt, keine Teile mit Länge ≤ 0.
3. `Anzahl Tablare = 1` → keine Division durch 0 bei den Tablarhöhen.
4. Tür nach innen mit Türbreite ≥ Seitenlänge → Seitensegment entfällt mit Warnung statt Crash.
5. Sehr kleiner Raum (600 × 600) selbststehend → mindestens 1 Modul, keine NaN.

Jede Zeile hat einen Test in Task 4/5 (`test/reduit.test.js`, Block «Randfälle»).

### Task 5: `reduit.js` Bauarten, Stützen, Spannweite, Kosten

**Files:** Modify `reduit.js`, `test/reduit.test.js`

**Interfaces (Produces):**
- `SPAN` Tabelle (Spec) + `maxSpan(mat, t)` (Fallback 700).
- `BUY` Preistabelle `{ key: { name, price, unit } }` (Startwerte als Schätzung; Task 7 ersetzt durch Jumbo).
- `supports = { battens, rails, brackets, cheeks, posts }`, je `(seg, levels, ctx) → void` (schreibt über `ctx.add`, `ctx.hw`, `ctx.extras`, `ctx.warn`).
- `freeModules(seg, levels, ctx)` für selbststehend.
- `computeReduit(c) → R` mit `kind:'reduit'`, `W:rw, H:rh, D:rd, Dtot:rd`, `rows, groups, boxes, doors:[], slides:[], extras, hw, finish, tools, steps, warn, level, carcFin, frontFin, matShort, Bk, joint, buyCost, solidCost, room`.

Regeln (Spec «Bauarten», «Durchbiegung»):
- Stützabstand: `pieces = floor(L / max) + 1` → jede Spannweite `L / pieces < max`.
- Leisten: Wandleiste je Tablar über die ganze Länge, Endleisten an Wand-Enden (Tiefe − 20), Eckleiste am Eck-Ende, Pfosten 45 × 45 am freien Ende; `L ≥ max` → Warnung Vorderkante.
- Schienen: 50 mm von den Enden eingerückt, `pieces(L − 100) + 1` Schienen, Konsolen je Schiene und Tablar; Schienenlänge aufgerundet auf 1000/1500/2000/2500; Konsolenlänge grösste aus 200/250/300/370/470 ≤ Tiefe − 10.
- Winkel: `pieces + 1` Winkel pro Tablar, Grösse kleinste aus 150/200/250/300 ≥ ⅔ Tiefe (sonst 300 + Warnung).
- Wangen: Felder `nb = floor((L − t) / max) + 1`; Nischenkante ist Feldgrenze; 4 Bodenträger pro Tablar, 3 Wandwinkel pro Wange.
- Pfostenrahmen: Pfosten vorne an beiden Enden (nicht am Eck-Ende) und je Spannweite; Querlatte vorne und Wandlatte je Tablar, Endlatten an Wand-Enden.
- Selbststehend: Module `m = ceil(L / min(900, max + 2t − 1))`, Seiten bis Boden, Böden auf allen `levels` (unterster = Boden, oberster = Deckel), Nischenmodul ohne Böden unter Nischenhöhe; Höhe > 1200 → Kippsicherung.
- Wandart Gipskarton → Hohlraumdübel + Warnung.

- [ ] Tests: Trägeranzahl bei L = 1600, Multiplex 18 (max 800 → pieces 3 → 4 Schienen); Leisten L ≥ max → Warnung; Wangen-Nische → Wange an Nischenkante; Modul-Aufteilung 1600 → 2 Module; MDF 19 → Modulbreite < 550; Pfosten am freien Ende; keine Teile mit L ≤ 0 oder NaN über alle 2 × 3 × 5 Kombinationen.
